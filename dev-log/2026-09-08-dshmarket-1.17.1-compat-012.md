# DSH 运行时升级 0.1.2-rc.1 — dshmarket 1.17.1 兼容专项结论（2026-09-08）

**结论：dshmarket 保持 1.17.1，不升级。兼容性由新增的 `patches/dsh-settings@0.1.2-rc.1.patch`（legacy API 恢复）保障，market 全量 441 基线升级后全绿。**

## 探测方法（上游 v2.0.4..v2.0.5 market 相关 commit 挖掘）

1. 上游在窗口内（370 commits）**没有为 0.1.2 运行时动过 dshmarket 版本**：`dshmarket@npm:1.38.1` 的 resolutions 行在 v2.0.4→v2.0.5 全程未变。1.17.1→1.38.1 的升级发生在更早的 `e225b0fb7d "chore(beta): prepare 2.0.5-beta.1"`（2026-09-01，runtime alpha.3 时代），动机是自更新命名/semver 预发布支持/ndjson 参数序（beta 产品功能），commit 文本与 diff 均无「0.1.2 兼容所需」表述。
2. **关键 API 依赖面**：dshmarket 1.17.1 的 `lib/settings.js` 直接 `import { installSettingsSection, settingsNamespace } from '@deepseek-ai/dsh-settings'` —— 正是 0.1.2 从 dsh-settings 移除的两个 legacy API。上游 dshmarket 1.38.1 的 peerDeps 显式写了 `^0.1.0-rc.7 || ^0.1.1-rc.2`（为 0.1.1 适配过），1.17.1 只有 `^0.1.0-rc.7`。
3. 因此 1.17.1 在 0.1.2 下的存活条件 = 我们恢复这两个 export。brief 要求新增的 `dsh-settings@0.1.2-rc.1.patch`（照抄上游 v2.0.5 同名补丁，恢复 `settingsNamespace`/`installSettingsSection`/`deepEqualJson` legacy 导出）恰好满足 —— 该补丁同时保住我们 `src/index.ts:80-83`、`notifications.ts:13` 的同款断链。
4. 客户端面：dshmarket 1.17.1 的 `client/client.js` 走 `window.__ModuleLoader__` 装载契约，与 0.1.2 客户端模块装载器同构（加载器契约未变）。

## 验证证据

- `yarn workspace dsh-community-market test`：**441/441 全绿**（含 contracts/install/signing/tarball-channel/signed-manifest-install/company-beta-channel 全套，覆盖 dshmarket 的安装路由、设置持久化与 Desktop 受控安装补丁面）。

- dshmarket 1.38.1 的自更新 UI 补丁（`dshmarket-npm-1.38.1-*.patch`）是其产品功能，按纪律不跟。
