# Brief — P14 换新规则分级 + Windows EBUSY 退避/deferred（2026-09-09 晚，回填）

## 1. Goal & background（目标与背景）

b78（0.1.2 过渡版，`pluginResetOnVersionChange:true`）首启换新失败：`plugin_reset {outcome:failed}` + 日志 `EBUSY: resource busy or locked, rename profiles\desktop -> desktop.bak-…`。实证根因=**外部进程持有 profile 目录句柄**：用户 Zed 打开 profile 内文件 → 编辑器 watcher 持目录句柄；逐个改子项全部成功、目录本身改不了。Linux 改名不惧句柄，故解包态单测全绿（第八次「Linux 绿 Windows 死」）。

目标三件：①自动层换新拆成两条可切换规则，避免每次发版都白清同事插件；②Windows 目录被占用时不再整次失败，改为退避重试 + deferred 标记下次启动续做；③市场台账回执不因「profile 空而回执在」钉死列表。

## 3. Conventions & constraints（约定与约束）

- 只改 desktop 自有代码；子模块与 policy 锁定层语义不弱化。
- 失败路径必须保证「旧 profile 仍可启动」；不写未来时态的臆测。
- 退避路径用注入 seam（`renameRetryDelaysMs`/`sleep`/`rename`）测试，不真等、不真持锁。
- 单测跑在 Linux，Windows 句柄语义须有专门 fake 覆盖。

## 4. Decisions made & failed attempts（已做决策与失败尝试）

- **内容级搬移兜底：已实现后按用户决策撤销**。`b2bfe99d7d` 曾实现「目录改名失败→逐项搬移内容」策略 B（含 `method: rename|content-move|none` 遥测），评审后用户判定场景罕见、不值复杂度，`e7f515da08` 干净回滚（含其 rollback、`method` 字段与测试），保留版本分级与两条复审修复。**后人勿重走此路。**
- 标记去留的闸=**策略 LOCK 单独**，不是版本开关：开关关时自动层仍会在产品版本变化时换新，指向非当前 profile 的标记必须保留。
- 关规则下「无记录」=首次观察（只 record、不 reset）；强制规则下「无记录+有 manifest」=跨版本残留（reset）。
- 恢复窗 deferred 不报失败，提示「重启后自动完成」，避免用户反复点按钮。

## 5. Acceptance criteria（验收标准）

- forced：`2.0.3+b78`→`2.0.3+b79` 触发换新；version：`+b78`→`+b79` 不动，`2.0.3`→`2.0.4` 换新。
- 目录被占：退避 6 次后写 `fresh-profile-pending.json` + 遥测 `outcome=deferred` + 不写版本记录；旧 profile 继续启动；下次启动最早时刻重试；标记指向非当前 profile 且策略锁定时保留。
- `plugin_reset` 带 `rule` 字段；恢复窗手动层不带。
- `record` 分支且 `profileExists=false` → 清残留回执；`profileExists=true` 绝不清。
- 真机：b78 首启 `outcome=failed`（EBUSY）已复现根因；修复后待下一次构建/首启复验 `outcome=swapped`（bak 出现 + 插件清空）。
