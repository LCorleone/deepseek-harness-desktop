# dsh-dai-context

**DeepSeek Harness 插件：Agent 上下文洞察与管理**

`dsh-dai-context` 是一个 DeepSeek Harness 插件，提供完整的上下文生命周期管理：

- **Context / 上下文 Tab** —— 会话内上下文统计、构成、趋势、事件与消息浏览的仪表盘。
- **`/context` 命令** —— 不离开聊天即可打开当前构成与浏览器。

> 与上游的差异：本分支**完全离线**（不发起任何网络请求，移除了 npm 版本检查），并**移除了 Plugin Info 卡片**。其余功能与上游一致。

## 安装 / 更新

由于本分支未发布到 npm，请用本地包安装（在 DSH 安装目录）：

```sh
dsh plugin --profile web add ./dsh-dai-context-0.41.3.tgz
```

更新时重新安装同名本地包即可覆盖。然后启动 Web UI：

```sh
dsh web
```

无需构建、无需重启。

## 使用

| 入口 | 说明 |
| --- | --- |
| **Context Tab** | 打开任意会话并点击 **Context / 上下文** 标签，查看完整仪表盘。 |
| **`/context` 命令** | 输入 `/context` 并回车，居中打开当前构成 + 上下文浏览器。 |
| **设置 → 插件配置** | 每用户偏好：趋势粒度、趋势模式、文件活动排序。 |

## 📊 Context Tab（卡片一览）

| 卡片 | 回答的问题 |
| --- | --- |
| **Context Stats（上下文统计）** | 轮次、步数、实时工具调用与图片、上下文事件计数；按 DeepSeek 官方刊例价估算全会话费用（悬停 `?` 查看 1M tokens 单价）。 |
| **Token Stats（Token 统计）** | 计费 token 去向：缓存读写、未缓存输入、输出 —— 围绕缓存命中环。 |
| **Timing Stats（耗时统计）** | 活跃时长在模型调用 / 工具执行 / 开销之间的分布。 |
| **Current Context（当前上下文）** | 窗口内**当下**的构成。 |
| **Context Trend（上下文趋势）** | 每次模型请求的尺寸与"故事"。 |
| **Context Browser（上下文浏览器）** | 任意请求*实际*由什么组装而成。 |
| **Context Events（上下文事件）** | 窗口何时、为何发生变化。 |
| **File Activity（文件活动）** | Agent 对文件做了什么。 |
| **Agent Network（Agent 网络）** | 整个 agent 家族的实时图谱。 |

头部占用与构成读取的是与聊天输入框上下文环**相同的官方 token 计量投影**（`contextPressure` / `contextBreakdown`），因此数字始终与输入框一致。

### Current Context —— 谁吃了预算

六色堆叠条对应模型完整窗口（斜纹 = 剩余空间）：系统提示、工具定义、用户消息、注入内容、助手回复、工具结果，各带 ≈token 数与占比。会话开始劣化时，这里能一眼看出是哪一部分的责任。

### Context Trend —— 每次请求都被量化和说明

每个模型请求一条堆叠条（粒度细于逐消息）：

- **Step brief** —— 图表下三行：**User** 本轮开启消息、**In** 新进入的内容（通常为上一轮工具结果）、**Response** 回复和/或调用的工具。点击某行跳转到浏览器中对应消息。
- **✂ 标记事件** —— 压缩/剪枝锚定在发生的那根柱子上，掉落自带解释。
- **Step / Turn 粒度**、**Total（累计构成）/ Delta（符号化变化）** 模式、整会话来回复制横向滚动。Delta 模式下增长堆积在基线之上，压缩则俯冲其下。
- **悬停与钉住** —— 悬停即时 tooltip，点击钉住完整分解；旁边并排供应商上报的 **Actual Prompt / Output / Cache** 与估算值。
- **实时联动** —— 悬停某柱子在旁边浏览器中预览该步组装后的上下文。

### Context Browser —— 打开任意请求的盒子

选择 **Live（下一次请求）** 或任意已保留步骤，浏览该请求的组装：六个可折叠类别 → 逐元素一行（带 token 价格）→ 每个元素再展开为**实际内容**（系统提示、每个工具 JSON schema、消息文本、推理、工具参数与输出）。

- **每个工具的提供方** —— 每条工具 schema 行带来源 chip：`tool-*` 一方包、`dsh-*` 能力包、`mcp:<server>` 代理、或从 `tools.register()` 实时监听到的具体插件。可按 **尺寸/名称** 排序，并按类别搜索过滤。
- **工具结果展开为完整调用** —— 工具名与参数及其 **OK/error** 状态、结果正文含行数与 **Raw / Markdown** 切换。
- **图片负载渲染为缩略卡片** —— 缩略图含名称、尺寸、存储大小与官方 DeepSeek 图片 token 估算。
- **与上一轮 diff** —— 每类别带符号增量徽章（`+N 项`、`±Nk tokens`）。早于压缩的步骤由已移除消息归档重建，卡片会在构成仅为近似时标注。

### Context Events —— 窗口何时、为何变化

每次注入、压缩、剪枝、模型切换、计划模式切换 —— 标注生产者（指令文件、插件 id、技能名）、净 token 增量（压缩展示回收量）、轮次/步骤与时间。**Inject / Compact / Prune / Switch / Mode** 芯片按种类过滤。

### File Activity —— Agent 对文件做了什么

每个被触碰文件一行（读 / 写 / 搜索），聚合到趋势图上选中的任意步骤：

- 按用途计数，头部 chip 兼作过滤器（**Read / Written / Searched / Images**）+ 路径搜索框。
- **行增量** —— 每次 `edit`/`write` 估算 `+加 / −删` 足迹，按文件与合计。
- 覆盖所有模式 —— 原生工具、Minimal 预设的 `str_replace_editor`、PTC `run_code` 内的嵌套调用，均归入逐工具行。
- 命中的真实文件获得带命中数的独立操作行。
- 点击某行展开完整操作日志，每次操作直达浏览器中的对应工具结果。

### Agent Network —— 家族图谱

当前 agent、其祖先、每一个子 agent —— 每 agent 一节点，血缘着色边，多级委托一图呈现。每环为该会话构成按其窗口占用缩放；悬停查看 token、请求、计费与活跃时长；点击跳入该会话的 Context Tab。运行中 agent 以绿色脉搏呼吸。

## ⌨️ `/context` 命令

输入 `/context`（或在 `/` 菜单中选取）并回车：居中对话框打开 **当前构成** 卡片与 **上下文浏览器**——与 Tab 相同的构成条、按步骤选择器、`vs 上轮` diff 徽章。该命令为**纯前端**实现：不派发到宿主、不写会话日志、不对模型可见。

## ⚙️ 设置

在 **设置 → 插件 → 插件配置** 的 **Context** 卡片含本插件每用户偏好：默认趋势粒度（Step / Turn）、默认趋势模式（Total / Delta）、文件活动默认排序。图内卡内的切换为局部视图，不覆盖存储偏好。

## 配置参数（cordis.yml）

插件 `config:` 块，全部可选（带默认值）：

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `maxRequestSteps` | `1500` | 保留的逐步请求记录上限（硬性步数兜底） |
| `maxKeptTurns` | `300` | 保留的最新整轮窗口（跨整轮裁剪，绝不半轮） |
| `maxEvents` | `400` | 保留的上下文事件数 |
| `maxNodes` | `2000` | 对外提供的表面节点数（新者优先，活动注入节点固定置顶） |
| `maxArchiveNodes` | `400` | 为逐步骤重建保留的已移除节点数 |

## 工作原理（数据平面）

宿主半区在 harness 的 `ctx.sessionProjections` 上注册两个**纯投影单元**，由框架按每个已提交的 `session/event` 增量折叠，检查点持久化到 `sessionProjectionCache`，并将完成值作为 `session/projection` 推送到浏览器：

- `contextTimeline` —— 当前构成、逐请求历史、上下文事件与模型可见表面。
- `contextHeaders` —— 请求头内容分 epoch 的元数据（内容按需按 seq 读取）。

浏览器半区通过框架标准 `useProjection(...)` 座位读取，**无轮询、无自定义 RPC、无客户端缓存**。

## 隐私与安全

本分支**完全离线**：宿主零网络 IO；浏览器端唯一的网络调用（npm registry 版本检查）已移除，插件 UI 不发起任何外部请求、不外发任何会话/文件数据。所有数据在 harness 本地。
